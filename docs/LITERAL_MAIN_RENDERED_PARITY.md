# Literal approved-main rendered parity — PP-WEB-42C

This source-only harness is admitted for the existing hosted GitHub font-readiness job only. Do not run its `main()` locally. Importing the pure policy/tests does not launch Playwright, browsers, HTTP servers, package installation or provider calls. Current publication approval remains required.

## Inputs and isolation

`tests/browser-main-parity.cjs` starts one 420-second monotonic deadline before either acquisition. Fixed `python3` argument arrays obtain approved main from `.pp-approved-main` through `scripts/export_main_snapshot.py`, then candidate through `scripts/export_candidate_snapshot.py --repository . --commit "$SOURCE_COMMIT"`. A full lowercase 40-digit commit claim is required. Subprocesses use no shell, have at most 70 seconds each, stdout at most 24 MiB and stderr at most 64 KiB; nonempty stderr/nonzero exit refuse. Raw payloads/errors are never logged.

The entrypoint refuses absent GitHub Actions/repository environment markers (an accidental-local-run guard, not cryptographic hosting attestation). The existing pure decoders authenticate fixed public path-to-blob mappings and defend returned byte buffers. Candidate commit/tree remain claims, not a verified commit chain. No worktree file fallback or generic filesystem HTTP server exists. The separately reviewed snapshot request handler serves only decoded admitted bytes, clean aliases and GET/HEAD. Local analytics and contact JavaScript are mocked empty. APIs/private paths cannot be served. Actual hosted servers bind ephemeral `127.0.0.1` only and are closed with browser/context on success, failure or global expiry. Final bounded cleanup verifies all three resource classes; a cleanup rejection/timeout forces both acceptance flags false and nonzero exit. The evidence directory and images are create-only, never overwritten on a retry.

Only exact HTTPS Google CSS `/css2` stylesheet and Google font-host font GETs are admitted. Redirects/retries are disabled. Each admitted URL is fetched once into a bounded byte cache and replayed on both sides; all other external dependencies are failures. Cache cap: 32 URLs, 2 MiB per response, 8 MiB aggregate after body receipt. This is not a streaming response-allocation bound. Request/response failure lists are bounded and overflow fails acceptance. No live analytics, form delivery or deployment is tested.

## Comparison

Strict sitemap syntax resolves exactly the 27 admitted public HTML paths. Both maps must agree. At widths 390 and 1440, the harness loads main then candidate sequentially in fresh pages, with reviewed reduced motion/device scale 1 and no custom Chromium flags. Normal Latin Inter weights 400/500/600/700/800 load on all pages; DM Serif Display 400 loads on the five existing routes. Each check must resolve real loaded matching-family, normal-style faces supporting the requested weight. Fonts have a finite five-second readiness limit, not a sleep/retry.

The existing capture-readiness helper decodes every image including lazy images using finite scrolling and restores scroll zero, then waits two animation frames. No CSS or DOM styles are patched, masked or normalized. First full-page PNGs only are retained and compared byte-for-byte. Geometry includes document/viewport dimensions and every image's rectangle, natural dimensions and selected currentSrc; only the known ephemeral local origin is removed from image URLs. No tolerance, later matching capture selection or renderer change is allowed.

Dimensions are admitted before capture: at most 2560 wide, 12000 high and 12 million pixels. A conservative `5 × pixels + height + 1 MiB` PNG reservation is charged before every independent capture. The reservation is refunded to actual bytes after a bounded write, or to zero only when the candidate's independently captured first Buffer is exactly equal to that same case's retained main Buffer. No hash-only or cross-case deduplication is allowed. Each candidate record keeps its actual first-capture SHA256, bytes, dimensions and geometry, plus an explicit `evidenceFile` and `storage`. For `deduplicated-equal-first-capture`, `evidenceFile` points to that case's physical main PNG; `name` remains a logical capture identifier, not a claim a second file exists. Unequal candidate first PNGs are physically retained before strict failure. Equal bytes do not waive geometry or other acceptance checks.

Total evidence cap remains 64 MiB, with 1 MiB reserved first for JSON, and at most 108 original PNGs plus one JSON (all 54 equal pairs produce 54 physical PNGs plus JSON). The original maximum109 reservation count remains, even when a candidate requires no additional physical file. Files use create-only writes; failed captures never overwrite first originals. Exceeding budgets fails and checkpoints; it never increases allowance, deletes artifacts or spends money. Output is only the `literal-main` subdirectory of existing `FONT_EVIDENCE_DIR`, uploaded by the already-existing artifact step.

This storage-only optimization follows hosted run47: 41 exact first-capture pairs passed, but its unchanged64MiB conservative reservation budget refused the next capture after49,130,076 physical PNG bytes. ## Acceptance and limits

`node --test tests/main-parity-policy.test.cjs` runs only source/pure/private-file tests. `node --check` checks source syntax. These do not prove actual runtime or pixels. Hosted execution must report all 54 unique route-width cases, strict PNG equality, exact geometry/image choices, successful real font loads, no unexpected traffic or request failures and no deadline overflow before setting `passed`/`visualAcceptance` true. Results start false and preserve failures and first images. The existing migration/font checks, packages, runner, budgets and artifact are unchanged by this source module; workflow integration belongs to the COO.

A literal-main mismatch is useful evidence, not authority to redesign or weaken gates. Diagnose the first bounded images/source before any repair. Hosted pixel results do not establish interaction correctness, full Unicode, physical-device compatibility, deployed privacy/firewall behavior or publication approval.
